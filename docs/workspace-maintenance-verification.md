# v1.3.0 验证记录

2026-10-17，Windows / Node.js 24.15.0 / Microsoft Edge。

## 已完成的三项优化

1. 统一 Prettier 格式，加入 Oxlint 和 `npm run check`，拆分导航、统计卡片、工作区状态与下载逻辑。Windows / Ubuntu CI 同时执行格式与静态检查。
2. 多个命名工作区，支持选择、保存、恢复、重命名、确认删除、备份导出与导入。旧单存档自动原子迁移；版本标记阻止其他标签页的过期覆盖。存档操作位于 Worker，页面只接收元信息。
3. 新增贡献指南、缺陷与功能建议表单、PR 模板；同步 README、更新记录和使用演示，发布需要相应仓库访问权限。

## 本地验证

- `npm run check` 通过：格式检查、Oxlint、58 项单元测试、3 项启动器单元测试、TypeScript 与生产构建。
- `npm run test:launcher:smoke`：1 项完整真实进程流程通过，覆盖中文路径、构建、复用、过期源码及端口冲突。
- `npm run test:e2e`：25 项浏览器测试通过，共 87 项测试。新增覆盖两个独立命名存档、重命名、原始数值字符串的备份往返、导入副本、确认删除、刷新恢复、旧槽位迁移、跨标签页冲突、无效文件保护与筛选上限。
- 存储单元测试使用真实 IndexedDB 接口实现 fake-indexeddb，并注入元信息写入时的配额异常，验证排队的数据写入与旧存档迁移均回滚，不留下部分写入。
- 备份单元测试覆盖非 ISO 日期、原始编号、所有分析设置、错误版本与 JSON、非法数值/日期、未知字段、128 MiB 文件上限与 64 MiB 保守文本预算。
- 50,000 行测试：25ms 计时器触发 41 次，最大主线程任务 200ms，低于 1000ms 回归阈值。结果仅针对本次样本与本机环境。
- 依赖安装审计：0 个已知漏洞；没有强制忽略 peer 依赖。Oxlint 适配现有 TypeScript 7，保留编译器严格检查。
- 桌面、手机、多工作区和导入截图仅使用合成数据。七帧操作演示覆盖搜索、图表切换、导入及两个命名存档之间的恢复。

## 独立复核与修正

- 复核发现备份可包含过多筛选条件，造成不必要的计算与界面负载。新增最多 32 个筛选条件、查询及筛选值最多 4096 字符的校验，同时约束界面、新存档及备份导入/导出，并补充单元与浏览器回归。
- 可信的旧本地存档读取及迁移仍保留原查询设置，不截断旧数据；超过新限制的设置需由用户调整后再次保存或导出。
- 修正贡献指南与缺陷表单中的备份扩展名为 `.json`。
- 四进程回归曾出现两项浏览器超时，分别复测均通过；将本地与 CI 的浏览器并发统一为 2 后，完整 25 项回归通过。

## 发布验证要求

独立复核后，使用同一提交推送 main，等待 Windows Edge / Ubuntu Chromium 全部 CI 成功，再创建 v1.3.0 标签、源码包、静态包和 SHA-256 校验文件。静态包需独立解压后通过 HTTP 服务验证 Worker、分析与存档；上传后核对附件摘要。

源码内的记录截至发布前检查点，最终发布状态以对应 GitHub Release 和 CI 为准。仓库保持私有，不加入公开托管、账号、后端或数据上传。
